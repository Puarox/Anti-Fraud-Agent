# W6：Agent 工程能力与岗位映射

日期：2026-10-26。

## 会话协作结论

- 从 DoVideoAI 会话吸收项目表达方式：先讲长视频证据问题，再讲分层设计、故障恢复、验证指标和真实限制；不照搬其 Java/MQ 架构或无依据性能数据。
- 从 OnCall Agent 会话吸收 JD 映射：工具契约、状态恢复、错误边界、安全控制、评测和运行观测比堆叠框架更有说服力；金睛鉴诈与 OnCall 应作为互补项目，不宣称 Multi-Agent。
- 两个会话共同建议先补“可验证效果、恢复能力、统一工具错误契约”。本阶段先补工具契约、失败观察和轨迹指标；更大的盲测集与进程重启任务恢复列为后续。

## 本阶段实现

- 新增 Agent 工具描述注册表，给规划输入提供动作用途、适用输入和副作用边界；可用动作仍由案件媒体和真实 URL 证据限制。
- Agent 观察统一增加契约版本、工具状态、来源/版本、证据编号、UTC 观察时间、限制说明、错误码和耗时。
- 工具异常被转成脱敏的 `ERROR` 观察，返回规划环供 Agent 有预算地换工具或停止；不回显异常消息，不自动重试。
- 报告新增 `metrics`：Planner 次数、工具调用数、规划与工具阶段耗时、工具错误、规划器错误和自动重试数。
- 调查页面轨迹显示步骤耗时与证据编号，案件摘要展示调用和耗时汇总。
- 新增 Agent JD 能力映射与面试表达材料：[`agent-jd-playbook.md`](../docs/agent-jd-playbook.md)。

## 验证

- Agent 单测覆盖新工具契约、真实观察驱动重规划、工具异常转观察、降级选择替代工具、PII 阻断和案件 Checkpoint 补充事实。
- 报告指标只汇总本地运行阶段耗时，不声称 API P95、Token 费用或并发吞吐。
- 自动重试目前为 0；需要重试时由 Planner 读取错误后在剩余调用预算中显式采取替代动作。

## 能力状态与边界

| 能力 | 状态 |
|---|---|
| ReAct/感知—行动—观察、案件级短期记忆、SQLite Checkpoint、用户补问 | 已有并有单测覆盖 |
| 工具描述、统一观察信封、失败后重规划、阶段耗时指标 | 本阶段新增 |
| 跨案件长期用户记忆、多 Agent 协作、人工审核队列 | 未实现，不作为项目卖点 |
| 盲测规模、Agent 相对固定工作流收益、RAG 真实 Recall@K/MRR | 待评测，现有 6 例动作烟测不构成准确率 |
| 跨进程持久任务队列、Checkpoint 故障注入与并发恢复 | 未实现；SQLite 案件状态不等于 Web Job 生命周期持久化 |
| OpenTelemetry/Prometheus、token/费用账单、P50/P95 | 未实现；当前仅记录一次调查内规划和工具步骤耗时 |
| 工具自动重试 | 未实现；自动重试数固定为 0 |

## 下一阶段建议与验收

1. 建立开发集和独立盲测集，覆盖欺诈/合法、信息不足、伪造/真实媒体、工具失败和弃权；同模型、同工具、同预算比较固定流程与 Agent。报告证据支持、弃权、调用数和耗时，不先报“准确率提升”。
2. 为 `QUEUED/RUNNING/NEEDS_INPUT/DONE/ERROR` 任务状态落盘并故障注入：规划中、工具完成后、等待补问时分别重启服务，验证案件 Checkpoint 可继续且工具不重复执行。
3. 扩展工具契约测试：空召回、无效 URL、依赖不可用、超时和重复动作分别验证 `MISS/UNKNOWN/ERROR` 语义及降级路径；仅对明确幂等的瞬态故障单独设计有限重试。
4. 扩大 RAG 语料和人工标注查询集，分别对 BM25、BGE、混合检索报告 Recall@K、MRR、来源正确率和引用正确率。
5. 固定硬件/模型/数据，采集冷启动和热运行分阶段耗时、模型 token、内存占用后，再讨论成本和 P95 指标。
