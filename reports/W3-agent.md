# W3：受控调查 Agent 运行时

日期：2026-10-25。

## 已完成的可运行部分

- 新增 LangGraph 状态图：`plan → execute → plan`，按动作路由到 `report`；状态保存在本机 SQLite Checkpoint。
- 调查工具目前只有本地权威知识检索和离线网址初检，均为只读。每轮保存模型动作、工具结果、预算与引用证据；最多 3 次工具调用，同参重复会被拦截。
- 模型凭空编造的网址不能进入网址工具；报告只保留引用了真实输入证据 ID 的规则命中，媒体真实性显式为 `UNKNOWN`。
- 新增用户补充事实 API，沿用同一案件状态和稳定的去敏占位符；测试中 `ASK_USER → 新事实 → SEARCH_KNOWLEDGE → FINISH` 跨轮继续。
- 本地下载 Qwen2.5-0.5B-Instruct 作为离线动作选择演示模型，不上传案件文本。Web 工作台可显示动作与工具轨迹。

## 验证

- 14 项离线测试通过；其中 Agent 图测试验证观察改变工具顺序、拒绝编造的网址、用户补充后沿 Checkpoint 继续。
- 本机 HTTP 实测：合成“公检法安全账户”案例由本地模型执行 `SEARCH_KNOWLEDGE → FINISH`；另一合成“客服屏幕共享+网址”案例执行 `SEARCH_KNOWLEDGE → ASK_USER`。动作与结果可在案件页面查看。

## 未通过的完整阶段门槛

- 0.5B 小模型曾返回不合规的复杂 JSON，因此演示版只让它从白名单中选择下一动作；查询由本地状态生成。它能体现工具观察循环，但**还不足以宣称具有可靠的开放式假设规划能力**。
- 尚无规模化困难案件测试证明动作选择、补问和停止决策合理，也未与固定工具流程做同预算对照。
- 当前仅同步 HTTP 调查；长视频异步任务、取消和完整人工复核队列未实现。生产环境不能用 Flask 开发服务器。
- Checkpoint 存在本机 SQLite，尚未做多进程并发或故障注入验证。
