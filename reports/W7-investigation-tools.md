# W7：案件调查工具扩展

## 背景

现有 Agent 可检索知识、核验线索 URL、查看媒体取证汇总或询问用户。扩展工具时优先选择能从本地案件证据直接得到、能留下可复查回执的能力，避免把静态目录包装成真实工具，也不新增未经核验的外部数据源。

## 新增能力

- `BUILD_EVIDENCE_TIMELINE`：按视频帧 `at_ms` 或 ASR 片段 `start_ms` 排序媒体线索；没有媒体时间的内容保留录入顺序，并明确说明这不代表真实事件顺序。
- `CHECK_EVIDENCE_GAPS`：检查转账状态、凭据披露、当前联系状态和独立核验等关键词是否出现，返回待确认字段和候选问题。未出现只表示未知，不表示事件没有发生；这是关键词提示，需结合上下文复核。
- `VERIFY_EVIDENCE_CHAIN`：检查风险规则、知识卡和工具观察引用的 evidence ID 是否能对应到案件证据或有效知识卡；仅检查结构关联，不验证证据内容真假。

三项动作注册进 `TOOL_SPECS` 和 Pydantic `Decision`，按案件条件动态加入 Planner 可用动作列表；执行结果作为结构化 observation 返回规划环。小模型 Planner 输入包含最近工具观察摘要，便于它依据新结果选择后续动作。UI 显示名称、结果概要、证据 ID 和限制说明。

## 调用预算与安全边界

- 单次调查工具调用上限由 4 提高至 6；LangGraph recursion limit 随预算同步增加，避免达到新预算前先触发图递归上限。
- 三个新增工具均只读本地 manifest、已处理 observation、规则和知识卡，不访问网络、不修改案件证据。
- 事实缺口检查不会直接自动追问；它把候选问题交回 Planner，是否进入 `ASK_USER` 仍由调查规划决定。
- 用户补充新事实会启动新一轮预算和工具可用集合；此前的调查轨迹仍保留，同一轮内的重复工具会被阻止。
- 证据时间工具不为无时间戳事实编造时间；证据链校验不把有效 ID 等同于可信内容。

## 当前验证状态

本阶段只做了代码和文档静态核对，没有运行自动化测试。新增工具的边界已在本文件和作品集手册说明；下一步应为每个工具补单元测试，覆盖空证据、乱序时间戳、重复 ID、无效引用、关键词误触发，以及工具观察如何影响下一步规划。
