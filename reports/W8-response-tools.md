# W8：面向受害者处置的业务工具

## 为什么做这一轮

上一轮工具主要整理证据编号、时间线和信息缺口，工程上可复查，但没有直接回答用户最着急的问题：还在被对方诱导时该怎么办、已经转账或透露凭据后先联系谁、联系银行或警方前要准备什么。

本轮新增两项面向案件处置的 Agent 工具，并把对应的官方公开处置资料加入本地 RAG 种子卡。来源分别是[上海市公安局发布的被骗后处置建议](https://www.shanghai.gov.cn/nw31406/20250527/ab65c2b8613447a9bcd8535363369efd.html)和[国家金融监督管理总局云南监管局关于屏幕共享诈骗的风险提示](https://www.nfra.gov.cn/branch/yunnan/view/pages/common/ItemDetail.html?docId=1226950&itemId=1952)。

## 新增工具

### `GET_RESPONSE_PLAYBOOK`：分场景止损建议

根据案件线索准备三类条件式建议：

- 对方仍在联系或要求继续操作：停止转账、共享屏幕和提供验证码，通过用户自己找到的官方渠道核实。
- 已转账、发现异常交易或支付凭据泄露：尽快联系开户银行/支付机构官方渠道申请保护账户，并尽快拨打 110 或联系公安机关；不承诺一定追回。
- 设备可能被远程控制：尽量使用另一台可信设备求助；若仍被控制，按银行/公安机关指引断开网络或关机；在可信设备上保护账户和修改密码。

工具只根据关键词找到相关证据编号，并把每条建议写成“如果该情况已经发生”的条件句。关键词命中不会被当成事件已确认；报告提醒用户直接联系银行或公安机关，Agent 不会代替止付、冻结或报案。

### `PREPARE_REPORTING_CHECKLIST`：联系银行/警方材料清单

把案件已有的证据编号、证据类型、检测到的网址主机、风险规则命中和媒体哈希汇总起来；再列出尚需准备的信息，例如首次联系时间、对方账号、交易金额/时间/渠道、透露过的信息、安装过的应用，以及联系银行/警方后的受理信息。它不复制银行卡密码、支付 PIN 或验证码，也不上传材料或提交报案。

## 接入方式

- 两项动作加入 Agent 白名单、Pydantic `Decision` 和运行时可用工具描述；有案件事实时由 Planner 按调查状态决定是否调用。
- 每次调用的结果、关联 evidence ID、来源 URL 和限制写入工具观察，继续返回 `plan → execute → plan` 循环。
- 案件页增加分场景建议和材料清单展示；19 项旧目录扩展到 24 项能力，其中 9 项可由 Planner 选择，单次最多 6 次调用。
- 知识卡从 3 条增加到 5 条；没有 BGE 权重时，RAG 仍可用 BM25 检索新增资料。

## 边界

这两项工具是基于公开指引生成的本地准备清单，不是自动化紧急响应服务。工具不会验证银行账户、联系公安、冻结资金、提交报案或保证追回；关键事实需要用户确认，实际处置应通过官方渠道完成。建议措辞和来源需要持续复核，特别是涉及急救式、跨地区或跨境情境时。

## 验证状态

已进行 Python/JavaScript 语法检查、工具目录数量核对和 Markdown 链接核对；本阶段没有运行自动化测试。下一步应为不同场景添加检查：未转账、疑似已转账、验证码已泄露、远程控制仍在进行、信息不足和误触发等；再由反诈业务人员审查建议的顺序、措辞和适用条件。
