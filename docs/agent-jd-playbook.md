# 金睛鉴诈：Agent 岗位能力映射与面试表达

本文按当前仓库实现整理。面试表达以代码、测试和阶段报告为准；未完成的计划不写成项目业绩。

## 一句话定位

> 面向视频、语音、截图和文字线索的隐私优先反诈调查助手：本地抽取和去敏证据，结合可追溯 RAG 与有限轮调查 Agent，生成带来源、风险依据和不确定性说明的案件报告。

推荐工程叙事：

```text
多模态输入 → 本地提取/去敏 → 规则初筛 → RAG 查证
→ Agent 规划工具 → 观察结果并重规划 → 可复查报告/用户补问
```

项目的重点是证据闭环、有限自主性和失败边界，不是模型数量或虚构的并发数字。

## Agent JD 能力映射

| 常见要求 | 当前实现 | 证据与边界 |
|---|---|---|
| ReAct / 感知—行动—观察 | LangGraph `plan → execute → plan`；工具观察进入下一轮 Planner 输入 | `tests/test_w3_agent.py` 验证新观察能改变下一工具；这是单 Agent 调查循环，不是 Multi-Agent。 |
| Planning 与结构化输出 | Pydantic `Decision` 限制动作枚举、查询、假设和理由；根据已执行工具收窄可用动作 | 0.5B 模型走白名单动作输出，开放式 JSON 规划仍需谨慎；现有小样本烟测不能证明规划准确率。 |
| Tool Calling / 工具契约 | `TOOL_SPECS` 描述输入和副作用；工具观察记录状态、结果、来源、证据 ID、时间、限制和耗时 | 工具均为只读。当前工具是知识检索、离线网址核验、媒体信号复核；不会对用户账户执行转账等操作。 |
| 动态重规划 | 查询结果、网址结果和媒体观察返回循环；重复工具被拦截；工具异常作为 `ERROR` 观察传回 Planner | 不做自动重试；Agent 可以在剩余预算内选择替代工具或停止。 |
| Memory / Checkpoint | SQLite 持久化 LangGraph 案件状态；事实、决策、工具观察作为案件工作记忆；新事实沿同一案件恢复 | 这是按案件隔离的短期工作记忆；权威知识库是经复核的 RAG 知识，不是用户画像或跨案件个人记忆。Web Job 队列状态仍为进程内存，服务重启可能丢失任务状态。 |
| Human-in-the-loop | Agent 可进入 `NEEDS_INPUT`，等待补充事实后再次运行；保留既有调查状态 | 目前是用户补问闭环，没有多角色人工审核工作台、值班队列或审计权限系统。 |
| Guardrails / 安全 | 动作白名单、工具预算、递归上限、重复调用拦截、URL 必须来自案件证据、Planner 输出 PII 门禁、媒体弃权语义 | 自动去敏不是公网服务的隐私保证；当前工作台仅绑定本机回环地址。 |
| Agent 可观测性 | 每次规划与工具回执都带耗时；报告汇总规划/工具调用数、耗时、错误和自动重试数 | 当前没有 OpenTelemetry、Prometheus、跨服务 Trace 或 token/费用账单统计。 |
| Evaluation | 单元测试覆盖重规划、Checkpoint 补充、编造 URL 拒绝、PII 阻断和工具错误降级；另有 6 例动作烟测 | 手写动作情境不是准确率基准；尚缺独立盲测集和同模型、同工具、同预算的固定工作流对照。 |

## 关键工程改动

- Agent 规划输入新增动态可用工具说明，帮助模型知道工具边界和适用输入。
- 只读工具现在使用统一观察字段：`contract_version`、`tool`、`status`、`signature`、`result`、`source`、`source_version`、`evidence_ids`、`observed_at`、`limitations`、`error_code`、`latency_ms`。
- 工具异常不再直接中断整份调查；错误类型进入观察和报告，Planner 可读取失败并尝试另一项受限动作。当前自动重试数固定为 0，避免重复执行和不透明重试。
- 报告新增 `metrics`：规划调用数、工具调用数、规划与工具累计耗时、工具错误数和自动重试数。
- Agent 轨迹页面展示阶段耗时和证据编号，可从每项观察回到案件证据。

## 面试时可这样讲

> 我把任务拆成了确定性证据预处理和受控的 Agent 调查循环。OCR、ASR、去敏、风险规则先在本地生成结构化证据；LangGraph Planner 在每轮只从当前可用的只读工具中选择动作，工具回执带状态、来源、证据编号和耗时，再回到 Planner 重新判断。相同工具参数会拦截，工具错误作为观察进入下一轮，预算耗尽或证据不足时停止或补问。SQLite Checkpoint 保存案件级工作状态。我们仍缺较大规模盲测和固定流程对照，因此不声称 Agent 已经提高诈骗识别准确率。

追问“为何不用固定工作流”时：固定预处理和即时高危规则由普通代码完成；Agent 只负责线索不完整、下一项核验取决于新观察的调查段。其价值需要通过同预算下的任务完成、证据支持、弃权和成本评测来证明，不能只靠画出循环图。

## 诚实的项目亮点写法

- 构建本地多模态反诈证据流水线，提取 OCR/ASR/二维码/视频帧线索并做规则去敏，生成可回查的 `evidence_id`。
- 基于 BM25、可选 BGE 向量召回与 RRF 融合构建来源可追溯的反诈知识检索；向量权重不可用时退化到 BM25。
- 基于 LangGraph 实现有限轮只读调查 Agent，具备工具白名单、按案件 Checkpoint、观察后重规划、用户补问、PII 门禁和调用预算。
- Agent 轨迹记录计划理由、工具状态、来源、证据编号和阶段耗时；用自动化测试验证工具错误后的安全重规划。

不要写“反诈准确率提升 X%”“支持 X 并发”“Deepfake 准确识别”“保护隐私 100%”或“生产级多 Agent 平台”，除非后续完成相应数据、评测和运行环境验证。

## 接下来最值的改进

1. 建立开发集和独立盲测集：覆盖诈骗/非诈骗、信息不足、合法合成媒体、外链、工具错误和弃权场景。对比同模型、同工具、同预算的固定工作流与 Agent。
2. 增加 Checkpoint 故障注入测试：在规划、工具完成、等待补问期间重启进程，验证案件状态和工具不重复执行；同时持久化 Job 生命周期，解决当前内存队列重启丢任务问题。
3. 扩展工具错误矩阵：空结果、超时、依赖缺失、非法输入、重复资源和模型拒答分别定义错误码、可恢复性与降级策略。只对明确幂等且瞬态的工具启用有限重试。
4. 采集冷启动/热启动耗时、OCR/ASR/RAG/Planner 分阶段资源、token 数和人工复核率，再决定是否建设 OpenTelemetry 或成本面板。
5. 只有在盲测显示调查任务可拆成独立且能并行的子问题后，再评估 Worker Agent；目前单 Agent 更容易控制证据一致性和审计链。

## 验收用指标建议

每个测试用例记录：下一动作可接受性、证据支持率、错误定论率、适当补问/弃权率、重复工具拦截率、工具失败后的安全降级率、调用次数和阶段耗时。检索单独报告 Recall@K、MRR、来源正确率；媒体检测单独按来源/压缩/真实与合成子域报告误报漏报。未收集数据前，报告“未评测”，不填预测数字。
