# 金睛鉴诈：多模态反诈调查原型

聊天截图、来电录音、短视频和用户描述经常一起出现。这个项目想解决一个实际问题：收到一条线索后，系统能不能把不同来源的信息放在一起核对，遇到证据不足时继续调查或向用户追问，并留下能复查的过程？

仓库基于已有竞赛项目源码做了本地化改造。原项目的 Flutter、React、Spring Boot 等模块仍在仓库中；新增的 Agent 工作台是一个独立的本地入口，目前没有接回原客户端和 Spring 链路。

## 先跑起来

工作台使用本地 Qwen 模型。权重没有放进 Git，首次运行前按[模型资产说明](docs/model_assets.md)准备模型。Windows PowerShell 下：

```powershell
cd "模型后端\模型后端\模型后端"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-local.txt
python local_web.py
```

打开 `http://127.0.0.1:5050`，点击“一键体验 Agent”。演示会创建一个合成案件，不需要填写真实个人信息。没有 BGE 或 Whisper 权重时，向量召回或音视频转写会按实现降级。模型下载位置和来源记录见[模型资产说明](docs/model_assets.md)。

## 演示里发生什么

样例案件包含“退款客服”“屏幕共享”“短信验证码”和一个示例网址。程序先做媒体线索提取、隐私替换和规则检查，再用 BM25 与可选 BGE 向量召回查找相关知识。Agent 根据当前观察选择下一项核验；例如网址工具返回 `UNKNOWN` 时，它不会把未知当成安全，而是可以继续检查其他线索或向用户补问。

## 为什么这里用了 Agent

媒体解码、脱敏、规则匹配和检索都由普通代码完成；这些步骤输入明确，不需要让模型自由决定。Agent 用在后续调查路径取决于新发现的地方：它读取案件状态，选择允许的工具，观察工具返回，再决定继续、换工具、追问还是结束。

当前 LangGraph 流程有调用预算和案件级 SQLite Checkpoint。工具失败会作为观察写入轨迹，Agent 可以据此调整计划；同参重复调用会被拦截。可选工具包含知识检索、网址核验、媒体取证检查和用户补问。工具说明及调用边界见[架构与运行路径](docs/architecture.md)。

这不是多 Agent 系统。这里的 Agent 是一个受限调查循环，工具结果也不是司法结论。

## 目前做到哪里

已有实现包括本地媒体线索处理、PII 替换、风险规则、BM25/BGE 混合检索、工具调用循环、补问与恢复、异步 Web 演示。仓库阶段记录覆盖单元和 Web 流程测试；此前完整测试运行结果为 21 项通过。测试说明工程流程符合这些用例，不代表模型识诈准确率。

当前知识库规模较小，缺少足量盲测数据和 Agent 与固定工作流的对照评估。AASIST/DFDS 相关输出仍是未校准的实验信号；陌生网址可能只能标记为未知。隐私替换也可能漏掉 OCR 错字、面部或声纹等信息。工作台只适合本机演示，任务状态保存在进程内存中，服务重启后可能丢失。

原始项目的分工和奖项证明不在仓库里。阅读代码时可以把 `APP/`、`前端/`、`Spring后端/` 视为原项目模块，把本地 Agent 工作台及 W0–W6 改造记录作为本仓库的后续工作线索；具体个人职责应以实际完成内容和可提供的证明为准。
